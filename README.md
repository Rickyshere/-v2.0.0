# 🚄 普速铁路中转方案网站

一个基于 **FastAPI + Leaflet + NetworkX** 的普速铁路（绿皮车 / K / Z / T）中转方案查询与可视化网站。输入起止城市或车站，即可在地图上展示两地之间的普速铁路行车路径、途经站点与中转枢纽，并可**查询 12306 实时直达车次**、沿**真实经停站**绘制直达线路，辅助铁路出行规划。

## 1. 项目简介

本项目根据**中国主要普速铁路干线**（京沪线、京广线、京九线、陇海线、沪昆线、京哈线等）构建一张铁路网络图，据此规划两城市之间的**最短普速铁路中转方案**。

数据**完全离线生成**：

- 以人工维护的线路清单元数据 `main_railway_line.txt` 为唯一数据源；
- 由 `upgrade_data.py` 生成站点表（`stations.csv`）与线路表（`lines.csv`）；
- 站点坐标由内置城市坐标兜底表补全，不依赖在线地图数据库；
- 可在网页内直接**编辑线路清单并热重载生效**，无需改动代码或重启服务。

> 路线规划基于离线路网；车次 / 经停站 / 余票等**实时信息**通过 12306、携程在线获取，仅作出行参考。

## 2. 核心特性

### 路线规划
- **最短路径**：基于 NetworkX 的 Dijkstra 算法求取里程最短路线。
- **同城多站合并**：算路时把同一城市多个站点合并为同一节点（如北京站 / 北京西站），规划"城市到城市"路线。
  > ⚠ 同一城市的两站若**没有归并**，分处两端的铁路线就**接不上**，整条走廊会断裂、算路被迫大绕行。典型：宁芜铁路止于「芜湖南」、皖赣铁路起于「芜湖」，不归并时 南京→黄山 会绕行上海·杭州算成 647km（实际约 275km）。
- **同城异站自动归并**：不再只靠手工表 —— 只要两个站名**有前缀关系**（芜湖 / 芜湖南、铜陵 / 铜陵西）且距离 ≤ 25km，就**自动归并**为同一城市。另有 `same_city.json` 供补充"站名无前缀关系但确属同城"的站对（如 中华门 / 南京），网页里可查看待确认的邻近站对。
- **具体站点呈现**：结果回落到路线实际经过的**具体车站**。
- **自动就近接入**：起点 / 终点若非特等、一等大站，自动就近连接到最近干线大站。
- **多方案对比**：一次返回多条不同走向的替代方案（默认 3 条）。
- **定制中转**：可强制经过一个或多个指定中转站（如 `武汉,郑州`）。
- **小站省会化**：可一键把线路小站替换为省会级大站展示，视觉更简明。

### 可视化地图
- Leaflet 用**不同颜色折线**绘制各方案，彩色圆点标出起点 / 终点 / 中转站，点击查看站名。
- **线路总览**：一键用不同颜色绘制全部铁路线路，附颜色图例、可点显隐、全显 / 全隐。

### 车次查询与直达线路
- **12306 实时车次**：手动触发查询任意区间的普速车次（K / Z / T / Y / 纯数字），带有串行限速 + 缓存 + 失败降级。
- **直达优先**：查询路线后自动在方案列表顶部展示"起点 → 终点"直达车次（若有）。
- **直达真实经停站**：直达车次若有多趟，自动选**耗时最短**的一趟，查询其**真实途经站点**（数据来自携程），在地图上沿这些站点绘制绿色折线，每站画绿色圆点，点击可查看站名与到开时间。
- **等级筛选**：直达线路中途站点**只重点展示特等 / 一等 / 二等站**，县级小站不点缀，避免地图噪音。
- **已选车次（分段拼装）**：查出的每条车次都可勾选"钉"到独立面板，**跨查询保留**，方便把 `A→B`、`B→C` 两段车次并排对照；两段首尾相接时自动提示换乘链，结果持久化到浏览器本地。
- **票价查询（可选）**：勾选「增加票价查询功能」后，车次会附带**无座 / 硬座 / 硬卧 / 软卧 / 二等座 / 一等座 / 商务座**等票价。票价直接解码 12306 同一次返回里的 `yp_info` 字段，**不产生额外请求**。无座按铁路规则等于硬座（普速）/ 二等座（动车）价，会以 `*` 标注为推导值。
- **电报码前置校验**：12306 接口只认**电报码**（如 芜湖 `WHH`），不认中文站名。`station_codes.csv` 提供站名 → 电报码对照（当前 230/241 站有码），网页「线路管理」会显示覆盖率并列出没有电报码的站（多为货运/技术站），避免"查不到车次"时无从排查。

### 高速动车组页面（独立页面）
- **八纵八横通道**：页面顶部可在**普速列车 / 高速动车组**之间切换。高速页面的路网依据 2016《中长期铁路网规划》的**八纵八横** 16 条主通道，按「是否通车」拆成 **35 段**（30 段参与算路 + 5 段 `[在建]`），为**车站级**骨架（**641 站 / 691 连接**）。
- **车次只查 G / D / C**：与普速页面的 K / Z / T / Y / 纯数字完全隔离。
- **功能与普速页面完全一致**：两个页面**共用同一套渲染与交互逻辑**，只切换「数据源 + 车次类别」，因此方案查询、地图、车次、直达、票价、已选车次、推荐方案、通道总览全部可用。

### 推荐方案（直达 / 中转）
- **一键推荐**：点「推荐方案」，系统先查直达，再用路网图找候选枢纽拼中转。
- **接续时间 ≥ 1 小时**：中转只保留接续时间不少于 60 分钟的组合（可调），并按总耗时排序。
- **支持次日接续**：普速常跨天（如 北京→南京 的 1461 次 11:59 发、次日 02:56 到），因此第二程会**同时查当日与次日**车次，否则普速中转几乎都会被判为不可行。

### 数据与扩展
- **动态加站（临时）**：在「线路管理」里填站名 + 经纬度 + 等级，即可把本地库中没有的站点加入路网，并自动接入**最近的大城**参与算路。
  > ⚠ **只在内存中生效，重启服务后失效** —— 要长期保留请把该站写进 `main_railway_line.txt`。表单与提示语里都写明了这一点。
  > 也可直接调 `POST /api/station/add`。
- **线路管理（热重载）**：网页内加载、编辑 `main_railway_line.txt` 线路清单，保存后自动重算路网并**热重载生效**，无需重启服务。
- **坐标自动补全**：新增线路若含缺坐标站点，可在网页里**勾选开关一键在线补全**（百度服务端 AK），也可用 `fetch_coords.py` 自动在线爬取或交互输入坐标，结果写入 `extra_coords.json`，生成数据时自动读取。
- **坐标安全防线**：坐标无效（缺省 `0,0` / 越界）的站点**不接入路网**，因此不会产生"上万公里的假边"把方案算飞；缺坐标站点会在网页上被列出来，补全后自动恢复。
- **坐标复核**：自动挑出"相邻站间距异常大"的区间供人工确认，用于发现**被地理编码解析到异地同名**的错误坐标（这类坐标看上去完全合法，靠有效性校验拦不住）。只报告、不自动改数据。
- **防误解析**：内置"相邻站距离合理性校验"与"易撞名纠偏表"（如 `沙城`、`新化`），防止小地名被在线地理编码解析到异地同名（如台湾 / 浙江）把线路拉飞。

## 3. 技术栈

| 层次 | 技术 | 用途 |
|------|------|------|
| 后端 | FastAPI + uvicorn | 提供 REST API、自动文档、静态页面 |
| 图算法 | NetworkX | 构建铁路网络图、Dijkstra 最短路径 |
| 前端 | 原生 HTML / CSS / JavaScript + Leaflet 1.9 | 地图渲染、查询表单、车次展示 |
| 数据 | CSV（UTF-8 带 BOM） | 站点表、线路连接表、电报码对照表 |
| 在线数据 | 12306 / 携程（实时车次与经停站） | 实时车次、直达经停站 |
| 坐标补全 | 百度 / 高德地理编码（Key 走系统环境变量） | 为缺坐标站点补全经纬度（并发 ≤3，仅在缺坐标时调用） |
| 电报码 | 12306 站名库快照（`station_name.js`） | 站名 → 电报码，12306 车次查询的前置依赖 |

## 4. 快速开始

### 4.1 环境要求
- Python **3.9+**
- 克隆或下载本项目后，进入项目根目录

### 4.2 安装依赖

```bash
# 建议创建虚拟环境（Windows）
python -m venv venv
venv\Scripts\activate

# macOS / Linux
python3 -m venv venv
source venv/bin/activate

# 安装依赖
pip install -r requirements.txt
```

### 4.3 一键启动（推荐）

- **Windows**：双击 `启动服务.bat`
- **macOS / Linux**：在终端运行 `bash 启动服务.sh`

> 首次运行会自动安装依赖、若 `stations.csv` / `lines.csv` 缺失则自动生成，随后启动服务并打开浏览器。

### 4.4 手动启动

```bash
python main.py
```

服务默认运行在 **http://127.0.0.1:8000**，浏览器访问即可使用。

交互式 API 文档：`http://127.0.0.1:8000/docs`

### 4.5 跑测试（可选）
项目带一套前端回归测试，用 [jsdom](https://github.com/jsdom/jsdom) 把真实的 `index.html`
载入模拟 DOM，stub 掉 `fetch` 与 Leaflet，**直接调用页面里的真实函数**做断言。

```bash
node tests/frontend/features_test.js   # 功能断言（46 项）
node tests/frontend/routes_test.js     # 路由对照（17 条路径）
```

| 脚本 | 作用 |
|------|------|
| `features_test.js` | 逐项验证功能：页面切换、车次类别、票价开关与折叠、推荐方案、收藏徽标等 |
| `routes_test.js` | **把前端请求过的 URL 和后端路由表做集合比对**，报出任何会 404 的路径 |

`routes_test.js` 是为了防一类事故：前端把 URL 拼错（曾把推荐方案拼成
`/api/hsr/recommend`，后端只有 `/api/recommend`），页面一直 404，
而**针对单个接口的断言用子串匹配根本抓不到**（`/api/hsr/recommend`
里也含 `/recommend`）。从路由表这一侧兜底，不依赖某个断言写得够不够严。

jsdom 是**可选的开发依赖**，不进 `requirements.txt`。脚本会自动在
`node_modules`、`JSDOM_PATH`、`tests/frontend/.testenv/` 等位置查找，
找不到会打印安装指引。详见 `tests/frontend/README.md`。

## 6. 使用说明

### 6.1 查询方案
1. 输入**起点 / 终点**（站名或城市名，如 `昆明`、`北京`）。
2. （可选）填写必需经过的**中转站**，如 `武汉,郑州`。
3. 选择**方案数**（1–5），点击 **查询方案**。

### 6.2 直达优先与真实经停站
- 查询后方案列表**顶部**出现绿色"直达推荐"卡片，展示直达车次（若有）。
- 若存在多趟直达车次，地图默认展示**耗时最短**一趟。
- 地图沿该车次**真实经停站**绘制绿色折线，每个经停站画绿色圆点（点击查看站名与到开时间）。
- **中途站点只重点展示特等 / 一等 / 二等站**，县级小站不点缀。
- 当日无直达则自动变淡，提示需中途换乘。

### 6.3 自定义区间查车次
每个方案卡片底部提供"✂ 自定义区间"选择器，可**任意选择两站组合**查询实时车次，搭配日期选择器（带后端限速 + 缓存 + 失败降级）。

### 6.4 已选车次（分段拼中转方案 A-B-C）
自己设计中转方案时，往往要分段查车次（先查 `A→B`，再查 `B→C`）。本功能让前一段的心仪车次**不会被后一次查询冲掉**：

1. 查询任一段车次后，每条车次**左侧出现勾选框**。
2. 勾选想要的那趟 → 该车次被钉到右侧「**已选车次**」面板，显示车次号、区间、日期、发到时间、历时与可否预订。
3. 继续查下一段（如 `B→C`）时，面板**保持不清空**，两段车次并排对照，便于判断接续时间。
4. 若已选车次首尾相接（`A→B` 且 `B→C`），面板顶部自动给出「**换乘链：A → B → C**」提示。
5. 「✕」移除单条，「清空」清空全部，「收起 / 展开」折叠面板。
6. 已选车次写入浏览器 `localStorage`（键 `railway_pinned_trains_v1`），刷新或重开浏览器不丢失。

> 勾选框在「直达推荐」卡片与每个方案的「自定义区间」结果中均可用。车次唯一键为 `车次号|出发站|到达站|日期`，因此同一趟车在不同区间/日期下可分别保留。

### 6.5 线路总览
顶部「线路总览」按钮，一键**在地图上绘制全部铁路线路**：每条线不同颜色、站点同色圆点、点击站点看站名与所属线路、右上角图例可单独显隐单条线、支持全显 / 全隐。

### 6.6 本地添加 / 修改铁路线（热重载）
1. 点顶部「线路管理」→「加载线路」，文本框显示当前清单。
2. 按格式新增 / 修改线路：

   ```
   线路名（可加注释）：站名（等级）、站名（等级）、站名（等级）...
   ```

   示例：
   ```
   南昆线（连接：南宁、昆明）
   南宁站（一等）、百色站（二等）、兴义站（二等）、昆明站（一等）
   ```
3. 点「保存并重新生成」→ 数据重算并**热重载到内存**，立即生效，无需重启服务。

> 等级支持：特等 / 一等 / 二等 / 三等。线名用「（）」括起来的文字视为注释。

> 💡 **临时加站**：若某个站在数据里没有，可在「线路管理」底部的「动态加站（临时）」
> 填站名 + 经纬度 + 等级，它会自动接入最近的大城并可立即查询。
> ⚠ 只在内存中生效，**重启服务后失效**；要长期保留请写进 `main_railway_line.txt`。

### 6.7 在线地理坐标补全（网页内一键补全）
新增线路里若有站点没有坐标，数据生成阶段会把它标成 `0,0`。这类站点**不会接入路网**（避免产生假边），并在网页上被列出。补全方式二选一：

**方式 A：网页内一键补全（推荐）**
1. 先把百度地图开放平台的**服务端 AK** 设为系统环境变量（见下）。
2. 打开「线路管理」，勾选底部开关：

   > ☐ 是否启用在线地理坐标补全，需提供百度地图开放平台服务端AK

   开关下方会实时显示 Key 状态与当前缺坐标的站点。
3. 点「保存并重新生成」或「从文件重新生成」，缺坐标站点会被自动补全，
   结果写入 `extra_coords.json` 并立即生效；反馈区会列出"已补全 / 仍失败 / 仍缺坐标"的站点。

**方式 B：命令行**
```bash
python fetch_coords.py --fix        # 在线爬取 + 交互输入
python upgrade_data.py --fetch      # 生成前自动补全
```

#### 配置百度服务端 AK
```powershell
# Windows 用户级环境变量（无需管理员），设置后需重启服务才生效
[Environment]::SetEnvironmentVariable('BAIDU_AK', '你的服务端AK', 'User')
```
也可用 `AMAP_KEY`（高德 Web 服务 Key）作为补充来源；`BAIDU_SK` 可选，配了就走 sn 签名规避 IP 白名单。

> ⚠ 必须是**服务端 AK**。浏览器端 AK 调用地理编码接口会返回 `status=240`。
> ⚠ 本项目不硬编码任何 Key，请勿把 Key 写进代码提交到公开仓库。

#### 额度与并发保护
在线地理编码每天有额度限制，因此：
- **仅当确实存在坐标无效的站点时才会发起请求**；坐标齐全时开关打开也不会消耗任何额度（接口会返回"未消耗额度"）。
- 百度对同一 AK 的**并发上限为 3**，代码里做了硬约束：`MAX_CONCURRENT_GEOCODE` 固定不超过 3（环境变量 `BAIDU_MAX_CONCURRENCY` 只能调低、不能调高），所有在线请求都经过统一的并发/频率闸门，线程池大小同样不超过 3。
- 请求间隔由 `BAIDU_MIN_INTERVAL` 控制（默认 0.34 秒）。
- 配置了国内 Key 后**不再兜底 Nominatim**（国内常连不通，白等约 10 秒）。

#### 坐标复核（超长区间提示）
在线地理编码对**异地同名**的小地名极易解析错 —— 实测「马鞍山」曾被解析到**广东境内**（`113.81, 22.72`），而安徽马鞍山应为 `118.51, 31.71`。这类错误坐标**看上去完全合法**（不是 `0,0`、也不越界），坐标有效性校验拦不住，但症状很明显：该站与相邻站的间距会异常大。

因此系统会自动挑出相邻站间距超过 `MAX_ADJACENT_KM`（默认 **900 km**，定义在 `upgrade_data.py`）的区间，在网页反馈区与 `GET /api/coords/status` 里列出：

```
⚠ 2 处相邻站间距异常大，请确认坐标是否正确：
  乌鲁木齐 — 西宁：1441.3 km（陇海—兰新线）
  中华门 — 马鞍山：1143.6 km（宁铜铁路）
```

**只报告，不自动处理** —— 因为兰新线（乌鲁木齐—西宁 1441km）、青藏线（拉萨—格尔木 828km）本身就是合法的长区间，用阈值自动删除会误伤真实数据。若异常区间出现在短途支线上，基本可以确定是地名被解析到异地同名，需要修正坐标（改 `extra_coords.json` 后重新生成即可）。

### 6.8 坐标补全（命令行）
上一节的网页开关是最省事的方式；若想用命令行（或需要在没有网页的情况下补全），用这一节的方式。当新增线路含缺坐标站点时，`upgrade_data.py` 会提示「站点 `xxx` 缺少坐标」。

```bash
# 只查看缺坐标的站
python fetch_coords.py

# 自动补全并重新生成（可选配置在线地理编码 Key）
python fetch_coords.py --fix --amap-key=你的高德Key --baidu-ak=你的百度Key
# 或用环境变量（推荐，避免 Key 出现在命令行）
set AMAP_KEY=你的高德Key
set BAIDU_AK=你的百度Key
python fetch_coords.py --fix

# 用补全结果重新生成路网
python upgrade_data.py

# 生成前顺带自动补全（一步到位）
python upgrade_data.py --fetch
```

结果写入 `extra_coords.json`，一次补全永久生效。

> ⚠ 命令行版 `fetch_coords.py --fix` 在爬不到时会进入**交互输入**（`input()`），
> 因此**不能**在 Web 请求里调用；网页开关走的是纯在线的 `autofill_online()`。

### 6.9 同城异站归并
同一城市常有多个车站（芜湖 / 芜湖南、铜陵 / 铜陵西）。如果它们**没有归并**，而恰好分处两条铁路的端点，**两条线就接不上** —— 走廊断裂，算路会大绕行。

归并分两层：

**① 自动归并（默认开启，安全规则）**
两个站名**有前缀关系**（A 是 B 的前缀，如 芜湖 / 芜湖南）**且**距离 ≤ 25km → 自动归并为同一城市（短名为主站）。

> ⚠ 为什么必须带"前缀"条件：**只靠距离会误判**。本数据集里 西安—咸阳 21.1km、株洲—湘潭 21.6km、太原—榆次 23.6km、丹阳—镇江 24.0km 都挨得很近，但分属**不同城市**；只按距离合并会把它们错并成一个节点。

**② 手工补充（`same_city.json`）**
站名无前缀关系但确属同城的（如 中华门 / 南京、广安门 / 北京），写在项目根目录的 `same_city.json` 里：

```json
{
  "manual": { "中华门": "南京", "广安门": "北京" },
  "auto_exclude": [],
  "auto": { "enabled": true, "max_km": 25, "require_prefix": true }
}
```
> JSON 不支持注释，因此**以下划线开头的键会被忽略**（如 `"_说明"`），可用来写备注。
> 改完保存，回网页点「从文件重新生成」即可生效。

**③ 待确认的邻近站对**
网页「线路管理」里会列出"距离很近但未归并"的站对，供人工判断。**只提示、不自动合并** —— 因为其中既有真同城（中华门—南京 5.5km），也有不同城市（西安—咸阳 21.1km），机器区分不了；距离 ≥18km 的会额外标注提醒。

> ⚠ 手工合并前建议先评估影响。实测把「月山」并进「焦作」会让焦作的城市等级从二等升到一等，进而失去"就近接入"的虚拟边，**部分线路反而变长 1362km** —— 这类副作用机器判断不了。

### 6.10 铁路电报码
12306 余票接口只认**电报码**（telecode，如 北京 `BJP`、芜湖 `WHH`），**不认中文站名**。因此没有电报码的站**查不到车次**。

- 对照表：`station_codes.csv`（列：站名 / 12306站名 / 电报码 / 类型）
- 用途：`railway_query.py` 查 12306 车次时把站名转成电报码
- 网页「线路管理」里有「铁路电报码」区块，显示覆盖率并列出没有电报码的站

**新增线路后如何补全电报码：**
```bash
python gen_station_codes.py      # 由 station_name.js 重新生成 station_codes.csv
```
它会从 `main_railway_line.txt` 取站点、从 `station_name.js`（12306 站名库）取电报码。生成后重启服务即可生效。

> 没有电报码的站多为**货运 / 技术站**（南仓、双桥、星火、广安门、马头…），本身就没有客运码，属正常现象，不影响路径规划，只是查不到 12306 车次。
>
> 若某个客运站也查不到码，多半是 `station_name.js` 太旧（该站是后来才有的），重新下载 12306 的站名库替换即可。

### 6.11 票价查询
勾选表单里的「**增加票价查询功能**」后，车次列表每行下方会多出一排票价标签：

```
1461  11:59 → 06:45  18:46  可预订
   无座*¥156.5  硬座¥156.5  硬卧¥283.5  软卧¥455.5
```

- 票价**不需要额外请求**：12306 在返回车次时已经带上了 `yp_info` 字段，
  每 10 个字符一组 = 席别(1) + 价格(5 位，单位「角」) + 尾数(4)。
  实测 1461 次解出 硬卧 283.5 / 软卧 455.5 / 硬座 156.5，与官方票价接口完全一致。
- `*` 表示**推导值**：无座票价与硬座（普速）/ 二等座（动车）相同是铁路固定规则，
  而 `yp_info` 里不含无座，所以按该规则推导并标注。
- 不勾选时完全不解析票价，响应更小。

**默认折叠的两处**：「**直达车次**」与「**推荐方案**」里的票价一律**默认收起**，
点「▸ 票价（N 个席别）」才展开 —— 这两处希望默认保持清爽。
它们**不受全局勾选框影响**，始终带上票价数据（反正不额外发请求），只是折叠起来：

```
直达  G307  07:05 → 17:54  10:49  直达，无需换乘
      ▸ 票价（4 个席别）          ← 点一下才展开
```

实现用的是原生 `<details>`，无需任何 JS 状态。

### 6.12 高速动车组页面
页面右上角有「**普速列车 / 高速动车组**」切换：

| | 普速列车 | 高速动车组 |
|---|---|---|
| 路网数据 | `main_railway_line.txt`（车站级） | `hsr_network.txt`（八纵八横，**车站级**） |
| 车次类别 | K / Z / T / Y / 纯数字 | G / D / C |
| 规模 | 241 站 / 233 连接（算路图） | **641 站 / 691 连接 / 35 段通道** |

两个页面**共用同一套渲染与交互**，只切换数据源与车次类别，所以功能完全一致。
切换时会清空上一个网络的方案，避免两套结果混在一起。

八纵八横通道数据（`hsr_network.txt`）按 2016《中长期铁路网规划》整理：

```
沿海通道：丹东、大连、秦皇岛、天津、东营、潍坊、青岛、连云港、盐城、南通、上海、宁波、福州、厦门、深圳、湛江、北海、防城港
京沪通道：北京、天津、济南、南京、上海
京港台通道：北京、衡水、菏泽、商丘、阜阳、合肥、九江、南昌、赣州、深圳、香港
京哈京港澳通道：哈尔滨、长春、沈阳、北京、石家庄、郑州、武汉、长沙、广州、深圳、香港
呼南通道：呼和浩特、大同、太原、洛阳、襄阳、常德、益阳、邵阳、永州、桂林、南宁
京昆通道：北京、雄安、太原、西安、成都、重庆、昆明
包银海通道：包头、延安、西安、重庆、贵阳、南宁、湛江、海口
兰西广通道：兰州、西宁、成都、重庆、贵阳、广州
（八横：绥满 / 京兰 / 青银 / 陆桥 / 沿江 / 沪昆 / 厦渝 / 广昆，详见文件）
```

> ⚠ **里程是「相邻车站直线距离」之和，与真实线路里程有偏差，且方向不定。**
> 实测 15 条主要干线：**-19% ~ +15%，平均 -7%**，其中 8 条在 ±10% 以内
> （车站级化之前，城市级骨架的偏差更大）。
> **这不是精确里程，准确里程与时刻一律以 12306 为准。**
>
> 数据体检：`hsr_planner.find_suspect_edges()` 扫相邻站距异常大的区段；
> `find_suspect_duplicates()` 扫「几乎重合但名字无关」的站 —— 后者是
> 地理编码抓错地点的强信号（实测「汉中」曾被解析到「佛坪」，相距仅 1.26km，
> 而它的站距 173.6km 落在合法长区间内，单靠距离阈值抓不到）。

> **在建段默认不参与算路**：通道名前加 `[在建]` 前缀即标记为未通车段
> （当前 5 段：京沪二线津潍段 / 潍宿段 / 北沿江段、京港台雄商段、京昆雄忻段）。
> 这些段**车站仍保留**（便于地图绘制），但**边不接入算路图** ——
> 否则会给出"查不到车次"的方案。实测：北京南→青岛北 由走京沪二线的 572km
> 变为走京沪+胶济的 **698km**（实际运营约 819km）。
>
> 想连在建段一起算：`POST /api/hsr/reload?include_planned=true`。
> 只在建段才有的站（如 东营南、滨州、泰州）查询时会明确提示
> 「目前只出现在在建通道「××」上，暂无车次」，而不是笼统的"不连通"。

> 通道数据是**人工整理的主要车站**，并经过「相邻站间距」自动校验
> （见 `hsr_planner.find_suspect_edges()`），但**不代表官方完整站表**：
> 部分县级小站、以及近年新开的车站可能未收录。

改完 `hsr_network.txt` 后点「从文件重新生成」不会重载高铁数据，需调用
`POST /api/hsr/reload`（或重启服务）。

### 6.13 推荐方案（直达 / 中转）
点表单里的「**推荐方案**」按钮：

- **直达**：列出当日直达车次（最多 3 趟）。
- **中转**：用路网图取每条方案上的**换乘大站**作为候选枢纽（最多 3 个），
  对每个枢纽分别查「起点→枢纽」「枢纽→终点」，只保留**接续时间 ≥ 60 分钟**的组合，
  按总耗时排序取前 5 条。

```
推荐方案：哈尔滨 → 南宁 · 2026-09-25　（中转接续不少于 60 分钟）
  中转  K4696 04:59→07:29 ＋ Z398 10:00→23:59   经 长春，接续 2h31m
  中转  K4696 04:59→08:57 ＋ Z398 11:08→23:59   经 四平，接续 2h11m
```

> ⚠ 该功能会查 `1 + 2×候选枢纽数` 次 12306（含次日接续查询），
> 受串行限速影响**约需 10 秒**，属正常。
> 接续时间下限可用 `min_transfer` 参数调整（默认 60 分钟）。

## 8. 关于在线接口与数据

- **路线规划**：完全离线，基于 `main_railway_line.txt` 生成的路网，不依赖在线服务。
- **12306 车次查询**（`railway_query.py`）：请求 12306 `leftTicket/queryG` 接口，解析返回的普速车次，仅保留 K / Z / T / Y 字头及纯数字。带**串行限速（≥1.6s/次）**、**60s 缓存**与**失败降级**。车次以 12306 实时为准。
- **直达经停站查询**（`ctrip_query.py`）：请求携程车次时刻页，返回真实停靠站序列，带 600s 缓存、失败降级，并内置防误解析校验。
- **坐标补全**（`fetch_coords.py`）：在线地理编码优先使用**百度 / 高德**（需自行申请 Key，走系统环境变量）。配了国内 Key 后**不再兜底** OpenStreetMap Nominatim（国内常连不通，白等约 10 秒）；未配 Key 时才尝试它。百度对同一 AK 的**并发上限为 3**，代码已做硬约束（信号量 + 最小间隔），且**仅在确实存在缺坐标站点时才会发起请求**（额度有限）。
- **电报码**（`station_codes.csv`）：12306 余票接口只认电报码，该表由 `gen_station_codes.py` 从 `station_name.js`（12306 站名库快照）生成，属**离线数据**，运行时不联网。
- 站点与线路数据为技术演示用途，**不代表真实铁路全貌**；实际运营、车次、余票请以 **12306 官方网站**为准。

## 9. 安全说明

- 本项目**不硬编码任何在线服务密钥**。
- 坐标自动补全所需的**高德 / 百度 Key** 请通过**环境变量**（`AMAP_KEY` / `BAIDU_AK` / `BAIDU_SK`）或**命令行参数**传入，**切勿**把自己的 Key 写死在 `fetch_coords.py` 并提交到公开仓库。
- 请勿提交运行时生成的日志文件（`*.log`）、`__pycache__/`、虚拟环境目录（`venv/`）等。
- 百度地理编码需申请「**服务端 AK**」才能调用 Web 服务接口（浏览器端 AK 会返回 `status=240`）；若后台设了 IP 白名单导致失败，可配置 `BAIDU_SK` 启用 sn 签名规避。
